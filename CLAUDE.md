# Matkasym Site - Инструкции для Claude

## Стек
- **Frontend:** React + Vite, развёрнут на Render
- **Backend:** Node.js + Express
- **База данных:** MongoDB Atlas (НЕ локальная!)
- **Изображения:** Cloudinary

## ВАЖНО: База данных

Локальный `server/.env` указывает на `localhost:27017` — это **НЕ** production база.
Товары живут в MongoDB Atlas.

**Пароли в репозиторий не пишем** — он публичный на GitHub. Строка подключения к боевой
базе лежит в `server/.env.atlas` (в `.gitignore`), в коде берётся так:

```javascript
const MONGO_URI = require('./lib/atlas');   // из server/scripts — '../lib/atlas'
```

Если файла нет, модуль честно скажет, что создать. Разово можно и через окружение:
`ATLAS_URI=… node scripts/имя.js`. На Render URI приходит из переменных сервиса
(`MONGO_URI`), этот модуль там не используется.

## Модель Product — обязательные поля

```javascript
{
  name: String,      // ОБЯЗАТЕЛЬНО! Используется для группировки в UI
  fullName: String,  // ОБЯЗАТЕЛЬНО!
  sku: String,       // Артикул (MKS-XXXX)
  brand: String,     // 'matkasym-home', 'matkasym-shaar'
  set: String,       // slug сета (например 'uzak-koldon')
  category: String,  // Категория товара
  price: Number,     // Цена (0 если priceUndefined: true)
  priceCost: Number, // Себестоимость / цена поставщика
  stock: Number,     // Количество на складе
  images: [String],  // URL картинок в Cloudinary
  isSupplied: Boolean, // true = привозной товар
  supplier: {
    company: String,   // Название поставщика
    sku: String        // Артикул у поставщика
  }
}
```

**НЕ использовать поле `title`** — его нет в модели!

## Поставщики (Suppliers)

При добавлении привозных товаров (isSupplied: true):
1. СНАЧАЛА создать поставщика в коллекции `suppliers`
2. ПОТОМ привязать товары

```javascript
// Модель Supplier
{
  name: String,      // Название компании
  phone: String,
  instagram: String,
  notes: String,
  products: [ObjectId] // Массив ID товаров
}
```

## Группировка товаров в UI

В `AdminSets.jsx` товары группируются по полю `name`:
```javascript
const grouped = {};
products.forEach(p => {
  if (!grouped[p.name]) grouped[p.name] = [];
  grouped[p.name].push(p);
});
```

Если у товаров одинаковый `name` — они отображаются как варианты одного товара!

### Данные и скрипты

**«Товар есть в каталоге» ≠ «у записи заполнен `product`»** (06.08.2026).
Считал каталожным любой товар, к которому привязана карточка, и увёл 27 заявок из
тестовой продажи в закуп. Но у большинства тестов привязана карточка, заведённая под
сам тест: `productStatus: 'test_sale'` (блок «ТЕСТ HOME» — без цены, без остатка) —
заказывать по ней нечего. Каталогом считаем только статус не из
`['test_sale', 'planned', 'in_development']` — хелпер `isCatalogProduct`
в `server/lib/productLaunch.js`. Тем же фильтром отбираем товары, среди которых ищем
совпадения: иначе тест матчится сам на себя с оценкой 1.00.

**Перед правкой боевых данных — предпросмотр и бэкап.**
Скрипты в `server/scripts/` пишем с флагом `--apply`: без него только печатают, что
изменится. Затронутые документы выгружаем в JSON до запуска — откат уже понадобился
(`undo-launch-reconcile.js`).

**`createdAt` не проставляется при `Product.create`.**
В схеме есть поле `isNew` — оно зарезервировано в Mongoose и ломает timestamps.
Товар уходит в хвост сортировки `{stock:-1, createdAt:-1}` и не попадает в первую
тысячу — визуально «товара нет». Проставлять `createdAt` вручную после вставки.

**Привозной товар без `isOnOrder: true` не виден.**
`AllCatalog` и `SetCatalogPanel` прячут его как «нет в наличии», даже если он заведён
правильно. Ставить флаг сразу при импорте.

**Пишем в `StockLog` — сверять со схемой.**
Роут приёмки писал по устаревшей (`action`/`oldValue`, `source: 'warehouse'` вне enum)
и отдавал 500 уже ПОСЛЕ сохранения остатка: пользователь видел ошибку, а остаток
менялся. Исправлено, в модель добавлены `source: 'warehouse'` и `note`.

### Фото и UI

**В `images` нельзя хранить URL с crop-трансформом в пути.**
`cloudinaryOpt` (client/src/utils/drive.js) вставляет `f_auto,q_auto,w_N` сразу после
`/upload/` — resize применится ДО crop и координаты поедут. Кроп «запекать» в отдельный
ассет и хранить чистый URL.

**Модалка открывается не по центру экрана — виноват `transform` у предка.**
`position: fixed` позиционируется относительно любого родителя с `transform`/`filter`/
`will-change`. В `Admin.css` было `.admin-page { animation: fadeInUp .28s both }` —
fill-mode `both` навсегда оставлял `transform` на обёртке. Не крутить стили самой
модалки, а: убрать fill-mode (или заканчивать keyframe на `transform: none`), а новые
модалки рендерить порталом в `document.body` (`createPortal`).

### Комплекты

- **Не делить общие детали** между комплектами — stock нужно распределять (как с
  кронштейнами PERSHULT).
- **Зависимые** (стол/стул, полка с кронштейнами): stock = min(stock детали / qty).
  Не хватает — «Не хватает деталей».
- **Независимые** (SKÅDIS, BOAXEL): детали самодостаточны — показывать бейдж
  «Комплект», НЕ показывать «Итого» и цену комплекта.
- Бейдж количества должен совпадать в карточке и в модалке.

### Печать PDF через headless Chrome

Каталоги и этикетки собираются как HTML → `chrome --headless=new --print-to-pdf`
(Puppeteer не установлен).

- **CSS Grid игнорирует `break-inside: avoid`** — карточки режутся на границе страницы.
  Лечится `display: flex; flex-wrap: wrap` у контейнера.
- **`break-after: avoid` у заголовка раздела** Chrome понимает как «не отрывать от всего
  следующего блока» и переносит раздел целиком.
- **Дефолтные `orphans/widows: 2`** не дают оставить на странице один ряд — ставить
  `orphans: 1; widows: 1` контейнеру.
- **Cloudinary-исходники по 5–6 МБ Chrome не успевает скачать** — подставлять
  `f_jpg,q_auto:good,w_900,c_limit` после `/image/upload/` (как `tgImage()` в `lib/telegram.js`).
- **macOS TCC:** Chrome не читает `~/Desktop` — рендерить из временной папки, вывод писать
  в `/private/tmp`, потом копировать.
