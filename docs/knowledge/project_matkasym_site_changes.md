Раздел /admin/site-changes в matkasym-site (21.11.2026). Роли owner + designer. Дизайнер пишет задачу (+скриншоты) → сервер шлёт repository_dispatch `site-change` → `.github/workflows/site-change.yml` запускает Claude Code CLI (модель claude-sonnet-5-5, только Read/Edit/Write/Glob/Grep) в ветке `design/<id>` → `.github/site-change/bot.mjs guard` откатывает всё вне client/src|client/public и api/, context/, roles.js → сборка (одна попытка починки) → PR → Render PR preview `matkasym-site-pr-N.onrender.com` → Telegram владельцу → «Принять» = dispatch `site-change-merge` (squash в main). Отчёты воркфлоу → `/api/site-changes/:id/callback` по секрету.

**Why:** пользователь хотел, чтобы дизайнеры тоже вайбкодили сайт без подключения каждого к проекту, а их правки проходили через его одобрение. Сначала выбрал общий API-ключ, потом (21.11.2026, коммит 4b61bde) — у каждого дизайнера своя подписка Claude (уже есть): «Мой Claude» в разделе, токен `claude setup-token` (sk-ant-oat01-, живёт год) шифруется в коллекции ClaudeToken, правку делает Claude того, кто её запустил (runBy). ANTHROPIC_API_KEY и месячный лимит в $ убраны.

**How to apply:** предпросмотр работает на БОЕВОЙ базе — в index.js при IS_PULL_REQUEST=true фоновые задачи пропускаются; при новых фоновых задачах класть их в тот же `if (!IS_PREVIEW)`.
